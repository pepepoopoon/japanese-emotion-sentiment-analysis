# Анализ тональности и эмоций японского текста

## Описание задачи

Один текст получает одну метку полярности (`negative`, `neutral`, `positive`) и любое
число из восьми эмоций Плутчика.

## Цель проекта

Реализовать объяснимый baseline без морфологического анализатора: символьные n-граммы
устойчивы к вариантам написания и не требуют внешних словарей.

## Архитектура решения

После NFKC-нормализации текста, проверки схемы и отсутствия Unicode-эквивалентных дублей
выполняется стратифицированный train/validation/test split. Тот же NFKC-контракт применяется
при инференсе. Общий char TF-IDF (2–5-граммы) питает логистическую регрессию полярности и
One-vs-Rest логистическую регрессию эмоций. Пороги эмоций подбираются только на
validation и вместе с моделями сохраняются в joblib bundle.

## Используемые технологии

Python 3.11, pandas, NumPy, scikit-learn, joblib, pytest и Ruff.

## Требования к окружению

Python 3.11 или 3.12. MeCab, словари и сетевые загрузки не требуются.

## Установка

```bash
python3.11 -m venv .venv
source .venv/bin/activate
python -m pip install -e ".[dev]"
```

## Подготовка данных

Контракт и условия WRIME описаны в [`data/README.md`](data/README.md). Синтетический
набор: `japanese-generate-smoke --output data/smoke.csv`.

## Запуск обучения

```bash
japanese-train --data data/smoke.csv --output-dir artifacts/smoke
```

## Запуск оценки

```bash
japanese-evaluate --model artifacts/smoke/model.joblib \
  --data artifacts/smoke/test.csv --output artifacts/smoke/test_metrics.json
```

## Запуск инференса

```bash
japanese-predict --model artifacts/smoke/model.joblib --text "合格して本当にうれしい"
```

## Метрики

Для полярности рассчитывается macro-F1. Для эмоций — micro-F1, macro-F1 и Hamming
loss после применения сохранённых поклассовых порогов.

## Тестирование

`pytest -q` проверяет схему, split, подбор порогов и end-to-end сценарий;
`ruff check .` выполняет линтинг. Тесты работают без сети.

## Ограничения

Smoke-данные не измеряют качество на живом японском языке. Бинаризация интенсивностей
теряет информацию, а char TF-IDF плохо переносит новый контекст. Нужны отдельный аудит
субъективных/объективных меток и проверка по авторам, если их ID доступны.

## Полученные результаты

Численные результаты на WRIME не заявляются. Метрики вычисляются CLI только на
фактически переданном наборе; синтетический прогон служит технической проверкой.

## Источник и лицензия данных

[WRIME](https://github.com/ids-cv/wrime) сейчас распространяется авторами под
CC BY-NC-ND 4.0. Это ограничивает коммерческое использование и производные
распространяемые копии. Исторические карточки также указывали research-only и запрет
redistribution. WRIME отсутствует в репозитории и должен получаться напрямую у авторов.
